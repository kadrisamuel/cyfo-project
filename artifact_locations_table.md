# macOS Artifact Locations — Script Reference Table

| # | Artifact Path | Scripts | Notes (Intel / Apple Silicon) |
|---|---------------|---------|-------------------------------|
| 1 | `/Library/Preferences/com.apple.Bluetooth.plist` | `reset_bt.sh`, `collect_state.sh`, `log_results.sh`, `01_baseline_collection.sh`, `02_artifact_discovery.sh` | **System-wide Bluetooth preferences plist.** Stores the paired-device registry (name, address, link key) and global BT settings. Present on **both Intel and Apple Silicon**. Protected by SIP on macOS 11+; `sudo` needed to read/write. On Apple Silicon (macOS 12+) much of the paired-device data migrated to `com.apple.MobileBluetooth.devices.plist`, so this file may be sparse or empty. |
| 2 | `/Library/Bluetooth/` *(directory tree)* | `reset_bt.sh`, `collect_state.sh`, `01_baseline_collection.sh`, `02_artifact_discovery.sh`, `03_post_forget_snapshot.sh`, `unified_drift_analysis.py` | **System Bluetooth data directory.** On **Intel (macOS ≤ 11)** this folder was mostly empty or held minimal daemon state. On **Apple Silicon / macOS 12+** it became the primary artifact store, containing `Library/Preferences/com.apple.MobileBluetooth.devices.plist` and the SQLite databases (see rows 3–5 below). Requires `sudo`; SIP-protected on newer releases. |
| 3 | `/Library/Bluetooth/Library/Preferences/com.apple.MobileBluetooth.devices.plist` | `collect_state.sh`, `01_baseline_collection.sh`, `02_artifact_discovery.sh`, `03_post_forget_snapshot.sh` | **Primary paired-device registry on Apple Silicon / macOS 12+.** Contains per-device dicts keyed by MAC address: name, class-of-device, link keys, connection timestamps. Typically **absent on Intel / macOS ≤ 11** where the legacy `/Library/Preferences/com.apple.Bluetooth.plist` was the primary source. `unified_drift_analysis.py` watches this file for flush events via Watchdog. |
| 4 | `/Library/Bluetooth/com.apple.MobileBluetooth.devices.plist` *(flat location fallback)* | `collect_state.sh` | **Fallback path** tried when the nested path (row 3) is absent. Observed on some Intel systems running macOS 10.15–11 where the MobileBluetooth subsystem was adopted but the directory hierarchy had not yet settled. |
| 5 | `/Library/Bluetooth/*.db` *(SQLite databases)* — specifically `com.apple.MobileBluetooth.ledevices.paired.db` and `com.apple.MobileBluetooth.ledevices.other.db` | `collect_state.sh`, `carve_ble.sh`, `unified_drift_analysis.py` | **BLE device SQLite stores.** `ledevices.paired.db` holds bonded BLE peripherals; `ledevices.other.db` holds seen-but-not-paired BLE devices. WAL-mode databases (`-wal`, `-shm` sidecar files). Present on **Apple Silicon** systems and on Intel macs running macOS 11+. The WAL flush timing of these files is the primary forensic signal measured by `unified_drift_analysis.py`. `carve_ble.sh` performs SQLite `.recover` and string carving against these databases. |
| 6 | `/private/var/db/blued/` | `collect_state.sh`, `02_artifact_discovery.sh` | **bluetoothd daemon state database (legacy).** On **Intel / macOS ≤ 10.15** this was a key persistence location (device cache, link keys). On **Apple Silicon / macOS 12+** `blued` was largely superseded by the MobileBluetooth subsystem and this directory is often empty or absent. Access requires `sudo`. |
| 7 | `/private/var/log/system.log` | `collect_state.sh` | **Legacy syslog.** On **Intel / macOS ≤ 10.14** (pre-Unified Logging) Bluetooth daemon messages were written here. On **Apple Silicon / macOS 10.15+** the Unified Logging System (ULS) replaced `system.log`; the file may exist but BT entries are absent — ULS (`log show`) is required instead. |
| 8 | `~/Library/Preferences/ByHost/com.apple.Bluetooth.<UUID>.plist` | `reset_bt.sh`, `collect_state.sh`, `log_results.sh` | **Per-host, per-user Bluetooth preferences.** Stores user-facing BT settings (discoverability, last-used device). The `<UUID>` suffix is the hardware UUID of the Mac, making it host-specific. Present on **both Intel and Apple Silicon**. Changes here affect only the current user session; the daemon reads system-level plists for pairing state. |
| 9 | `~/Library/Preferences/com.apple.bluetooth.plist` *(user-level, lowercase 'b')* | `reset_bt.sh`, `collect_state.sh`, `log_results.sh`, `01_baseline_collection.sh` | **User-level Bluetooth preferences (lowercase variant).** Stores per-user BT settings distinct from the ByHost plist. Seen on **Intel and early Apple Silicon** systems; on recent macOS releases this file is often empty or absent as settings consolidated elsewhere. |
| 10 | `~/Library/Preferences/com.apple.bluetoothuserd.plist` | `reset_bt.sh`, `collect_state.sh`, `log_results.sh` | **bluetoothuserd (user-space BT daemon) preferences.** Governs user-facing BT UI state. Present on **both architectures** but more relevant on **Intel / macOS ≤ 12**; on Apple Silicon with macOS 13+ the daemon was further integrated into system services and this plist may be sparse. |
| 11 | `~/Library/Preferences/MobileMeAccounts.plist` | `collect_state.sh`, `01_baseline_collection.sh` *(via `defaults read MobileMeAccounts`)* | **iCloud / Apple ID account state.** Lists configured Apple IDs, iCloud services enabled, and persona identifiers. Identical location and schema on **both Intel and Apple Silicon**. Used in RQ3 to correlate iCloud account presence with BT sync behaviour. |
| 12 | `~/Library/SyncedPreferences/` | `01_baseline_collection.sh`, `03_post_forget_snapshot.sh` | **iCloud-synced preferences channel.** Contains per-bundle preference plists that are synchronised across devices via CloudKit. On **Apple Silicon / macOS 12+** BT-related entries (e.g., `com.apple.MobileBluetooth`) may appear here after a "Forget Device" event. On **Intel / older macOS** this directory exists but BT entries are rarely populated. Key RQ3 artefact location. |
| 13 | `~/Library/Bluetooth/` *(user-scoped)* | `01_baseline_collection.sh`, `03_post_forget_snapshot.sh` | **User-scoped Bluetooth directory.** Typically empty or absent; some accessory SDKs (e.g., MFi accessories, AirPods personalisation) write user-specific config here. Behaviour is the same on **Intel and Apple Silicon**, though more data may appear on Apple Silicon where accessory features are richer. |
| 14 | `~/Library/Mobile Documents/` *(iCloud Drive container root)* | `01_baseline_collection.sh` | **iCloud Drive document containers.** Inventoried to detect whether any BT-adjacent app (e.g., Find My, Health) stores device identifiers in iCloud Drive. Present and identical in structure on **both architectures**; volume of data is user/app-dependent. |
| 15 | Keychain *(via `security find-generic-password -s "Bluetooth"`)* | `01_baseline_collection.sh`, `03_post_forget_snapshot.sh` | **macOS Keychain — Bluetooth secrets.** May contain link keys or pairing secrets stored by accessory companion apps. On **Intel** the system keychain is stored in `/Library/Keychains/`; on **Apple Silicon** it additionally interacts with the Secure Enclave. The `security` CLI abstracts the difference, so the scripts are portable across both. |

---

> [!NOTE]
> Path prefix `~` expands to the home directory of the user running the script (typically `/Users/<username>`). Paths beginning with `/Library/` or `/private/var/` are system-scoped and require `sudo`.

> [!IMPORTANT]
> The primary forensic pivot point between architectures is **row 3** (`com.apple.MobileBluetooth.devices.plist` inside `/Library/Bluetooth/`): this file is the dominant paired-device store on Apple Silicon / macOS 12+ but is absent or unused on Intel / macOS ≤ 11, where **row 1** (`/Library/Preferences/com.apple.Bluetooth.plist`) plays that role instead.
